# Описание классов банкомата

## `BaseAtmState.java`

Этот класс отвечает исключительно за **хранение состояния** банкомата, а именно — за учет имеющихся в нем банкнот.

### Основные функции:

*   Хранит количество банкнот каждого номинала в виде `Map<Nominal, Integer>`. В качестве реализации для `Map` используется `TreeMap`, хранящая номиналы в порядке убывания.
*   Позволяет добавлять банкноты (`put`).
*   Позволяет изымать банкноты (`remove`), выполняя проверку на достаточность средств.
*   Предоставляет информацию о текущем общем балансе (`getBalance`).
*   Позволяет получить информацию о минимальном доступном номинале (`getMinNominal`).

### Преимущества реализации:

1.  **Принцип единой ответственности (Single Responsibility Principle):** Класс сфокусирован только на управлении коллекцией банкнот.
2.  **Инкапсуляция:** Внутренняя структура данных скрыта. Все изменения проходят через публичные методы, что защищает состояние от некорректных изменений.
3.  **Простота тестирования:** Класс можно легко тестировать в изоляции, проверяя корректность добавления, изъятия и расчета баланса.
4.  **Повторное использование:** Реализацию состояния можно использовать с разными типами банкоматов, которые могут иметь разную логику операций.

## `BaseATM.java`

Этот класс представляет собой **базовую реализацию логики банкомата**. Он отвечает за выполнение операций, таких как снятие и пополнение наличных.

### Основные функции:

*   Использует объект `BaseAtmState` для управления своим состоянием.
*   **`withdraw(Integer withdrawalAmount)`**: Основная функция для снятия наличных.
    *   Проверяет, что запрашиваемая сумма не превышает баланс и кратна минимальному доступному номиналу.
    *   Реализует "жадный" алгоритм подбора банкнот для выдачи (начиная с самых крупных).
    *   Если точную сумму выдать невозможно, выбрасывает информативное исключение с предложением ближайших доступных сумм.
    *   Обновляет состояние `BaseAtmState` после успешной выдачи.
*   **`topUp(Map<Nominal, Integer> topUpBanknotes)`**: Позволяет вносить наличные в банкомат.

### Преимущества реализации:

1.  **Разделение ответственности (Separation of Concerns):** Класс сфокусирован на *процессах* и *бизнес-логике*, делегируя хранение данных классу `BaseAtmState`.

## Сравнение `AtmState` и `BaseAtmState`

`AtmState` вводит два ключевых дополнения: поддержку мультивалютности и механизм резервирования средств.

### 1. Дополнение: Мультивалютность

*   **Чем отличается:**
    *   Главное отличие — в структуре хранения данных. Вместо `Map<Nominal, Integer>` используется `Map<Currency, Map<Nominal, Integer>>`. Это позволяет банкомату одновременно хранить и управлять банкнотами **разных валют**.
    *   Все методы (`getBalance`, `getBanknotes` и т.д.) теперь требуют указания `Currency` в качестве аргумента, чтобы явно указывать с какой валютой производится операция.

*   **Для чего это нужно:**
    *   Это дополнение является ключевым для создания мультивалютных банкоматов, таких как `MulticurrencyATM` и `ReservationATM`.

### 2. Дополнение: Резервирование средств

*   **Чем отличается:**
    *   В `AtmState` добавлено новое поле: `Map<UUID, Map<Currency, Map<Nominal, Integer>>> reservation` для хранения зарезервированных купюр.
    *   Для управления этим хранилищем добавлены новые методы: `putReservation`, `containsReservation`, `removeReservation`.

*   **Для чего это нужно:**
    *   Это дополнение необходимо для реализации функционала резервирования денег в банкомате.

## `MulticurrencyATM.java`

`MulticurrencyATM` — это усовершенствование `BaseATM` для обработки нескольких валют.

**Ключевые дополнения:**
*   **Использование `AtmState`:** Переход на объект состояния, способный управлять несколькими валютами.
*   **Изменение API:** Добавление параметра Currency в методы, чтобы явно указывать с какой валютой производится операция.
*   **Адаптация внутренней логики:** Передача объекта currency во все методы объекта состояния.

## `ReservationATM.java`

**Детали реализации:**
*   Это более сложная и продвинутая реализация банкомата, которая добавляет возможность резервирования средств.
*   Как и `MulticurrencyATM`, он использует `AtmState` для управления состоянием.
*   **Ключевая особенность** — использование блокировок (`currency.getLock().lock()`). Операции `withdraw`, `reserve` и `topUp` используют блокировку для конкретной валюты. Это предотвращает состояние гонки, когда несколько потоков (клиентов) одновременно пытаются выполнить операции с одной и той же валютой.
*   Использование повалютных блокировок (`fine-grained locking`) является эффективной стратегией. Это позволяет одновременно без конфликтов проводить операции с *разными* валютами, что повышает производительность системы.
*   Метод `reserve` позволяет зарезервировать определенную сумму. Он генерирует уникальный `UUID` для резерва, изымает банкноты из общего доступа и помещает их в хранилище резервов в `AtmState`.
*   Использует `ExpiredReservationScheduler` для автоматической отмены резерва по истечении времени, возвращая деньги в общий доступ.
*   Метод `withdrawReservation` позволяет снять ранее зарезервированную сумму по ее `UUID`.
